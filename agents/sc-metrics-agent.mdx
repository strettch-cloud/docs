---
title: "SC Metrics Agent"
description: "The SC Metrics Agent runs on a compute and sends the values behind the compute graphs. How to install, manage and repair it."
---

The SC Metrics Agent is a small program on your compute that reads its CPU, memory, disk, network and load, and sends the values to Strettch Cloud. The [compute graphs](/services/compute/compute-graphs) are drawn from them. The agent is installed on every compute you create, and its [source code is on GitHub](https://github.com/strettch-cloud/sc-metrics-agent).

**Supported systems:** Ubuntu 20.04 and newer, Debian 8 and newer.

The graphs appear on the compute's **Monitoring** tab within a few minutes after you create a compute.

## Install the agent yourself

You need this only if the agent was removed from a compute.

```bash
curl -sSL https://repo.cloud.strettch.com/metrics/install.sh | sudo bash
```

The script finds your system, adds the Strettch Cloud package repository and installs the `sc-metrics-agent` package. To read the script before you run it:

```bash
curl -sSL https://repo.cloud.strettch.com/metrics/install.sh
```

Then check that the agent runs:

```bash
systemctl status sc-metrics-agent
```

You should see this line:

```text
Active: active (running)
```

The graphs fill in within a few minutes.

## Manage the agent

<CodeGroup>
```bash Check status
systemctl status sc-metrics-agent
```

```bash Restart
sudo systemctl restart sc-metrics-agent
```

```bash Stop
sudo systemctl stop sc-metrics-agent
```

```bash Start
sudo systemctl start sc-metrics-agent
```

```bash Start at boot
sudo systemctl enable sc-metrics-agent
```

```bash Do not start at boot
sudo systemctl disable sc-metrics-agent
```
</CodeGroup>

To see which version is installed:

```bash
dpkg -l | grep sc-metrics-agent
```

## Read the logs

<CodeGroup>
```bash Live
sudo journalctl -u sc-metrics-agent -f
```

```bash Last hour
sudo journalctl -u sc-metrics-agent --since=1h
```

```bash Last 100 lines
sudo journalctl -u sc-metrics-agent -n 100
```
</CodeGroup>

## Updates

The agent updates itself. To update it now:

```bash
sudo systemctl start sc-metrics-agent-updater
```

To follow the update:

```bash
sudo journalctl -u sc-metrics-agent-updater -f
```

## Uninstall the agent

Without the agent, the compute graphs stay empty.

```bash
sudo apt-get purge sc-metrics-agent
```

## The graphs are empty

[Connect to the compute](/services/compute/connect-to-a-compute) and go through these checks in order.

**1. Is the agent running?**

```bash
systemctl status sc-metrics-agent
```

You should see `Active: active (running)`.

- If you see `inactive (dead)` or `failed`, restart the agent:

  ```bash
  sudo systemctl restart sc-metrics-agent
  ```

- If you see `could not be found`, the agent is not installed. [Install it](#install-the-agent-yourself).

**2. Does the agent report errors?**

```bash
sudo journalctl -u sc-metrics-agent -n 50
```

**3. Look at the graphs again**

Wait a few minutes, then open the **Monitoring** tab.

**If the graphs are still empty**, email [cloud@strettch.com](mailto:cloud@strettch.com) with:

- the name of the compute;
- the output of `systemctl status sc-metrics-agent`;
- the output of `sudo journalctl -u sc-metrics-agent -n 100`;
- what you see on the **Monitoring** tab.

## Security

The agent encrypts the values it sends to Strettch Cloud. It runs with only the privileges it needs.
