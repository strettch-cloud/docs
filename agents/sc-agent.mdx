The SC Agent is a small program on your compute that makes the web console work. It is installed on every compute you create, and its [source code is on GitHub](https://github.com/strettch-cloud/sc-agent).

**Supported systems:** Ubuntu 20.04 and newer, Debian 8 and newer.

## When the web console is ready

The web console is ready within a few minutes after you create a compute. Until then, the console button on the compute's page reads **Setting up your console**.

The compute must be running. The web console does not open on a compute that is turned off.

## How the web console logs you in

The web console logs you in as `root` without a password. This is the same for a compute created with a root password and for one created with an SSH key, and the compute does not need a public IP.

It needs two ports open on the compute: TCP 22 and UDP 60124. If you run your own firewall on the compute, keep both open.

See [Connect to a compute](/services/compute/connect-to-a-compute#open-the-web-console) for the steps.

## Install the agent yourself

You need this only if the agent was removed from a compute.

```bash
curl -sSL https://repo.cloud.strettch.com/console/install.sh | sudo bash
```

The script finds your system, adds the Strettch Cloud package repository and installs the `sc-console-agent` package. To read the script before you run it:

```bash
curl -sSL https://repo.cloud.strettch.com/console/install.sh
```

Then check that the agent runs:

```bash
systemctl status sc-console-agent
```

You should see this line:

```text
Active: active (running)
```

The web console is ready within a few minutes.

## Manage the agent

<CodeGroup>
```bash Check status
systemctl status sc-console-agent
```

```bash Restart
sudo systemctl restart sc-console-agent
```

```bash Stop
sudo systemctl stop sc-console-agent
```

```bash Start
sudo systemctl start sc-console-agent
```

```bash Start at boot
sudo systemctl enable sc-console-agent
```

```bash Do not start at boot
sudo systemctl disable sc-console-agent
```
</CodeGroup>

To see which version is installed:

```bash
dpkg -l | grep sc-console-agent
```

## Read the logs

<CodeGroup>
```bash Live
sudo journalctl -u sc-console-agent -f
```

```bash Last hour
sudo journalctl -u sc-console-agent --since=1h
```

```bash Last 100 lines
sudo journalctl -u sc-console-agent -n 100
```
</CodeGroup>

## Updates

The agent updates itself. To update it now:

```bash
sudo systemctl start sc-console-agent-updater
```

To follow the update:

```bash
sudo journalctl -u sc-console-agent-updater -f
```

## Uninstall the agent

Without the agent, the web console does not work, and you can reach the compute only over SSH.

```bash
sudo apt-get purge sc-console-agent
```

## The web console does not open

The console tab shows **SSH connection failed**, or the console button stays on **Setting up your console**.

First connect to the compute [over SSH](/services/compute/connect-to-a-compute#connect-over-ssh):

```bash
ssh root@YOUR_COMPUTE_IP -p 222
```

Then go through these checks in order.

**1. Is the agent running?**

```bash
systemctl status sc-console-agent
```

You should see `Active: active (running)`.

- If you see `inactive (dead)` or `failed`, restart the agent and make it start at boot:

  ```bash
  sudo systemctl restart sc-console-agent
  sudo systemctl enable sc-console-agent
  ```

- If you see `could not be found`, the agent is not installed. [Install it](#install-the-agent-yourself).

**2. Are the two ports open?**

```bash
sudo ss --listening --numeric --tcp --udp | grep --extended-regexp ':(22|60124)\b'
```

You should see port 22 as `LISTEN` and port 60124 as `UNCONN`.

If a firewall on the compute blocks them, allow them:

<CodeGroup>
```bash ufw
sudo ufw allow 22/tcp
sudo ufw allow 60124/udp
```

```bash iptables
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
sudo iptables -A INPUT -p udp --dport 60124 -j ACCEPT
```
</CodeGroup>

**3. Try the web console again**

Wait 30 to 60 seconds, then open the web console.

**If it still does not open**, email [cloud@strettch.com](mailto:cloud@strettch.com) with:

- the name of the compute;
- the output of `systemctl status sc-console-agent`;
- the output of `sudo journalctl -u sc-console-agent -n 100`.

## Security

The agent encrypts its communication and checks cryptographic signatures. It runs with only the privileges it needs.
