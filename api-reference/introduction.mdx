The Strettch Cloud API lets you create and manage computes from your own code. It is a REST API: you send JSON, and every answer is JSON.

## Base URL

```bash
https://api.strettch.cloud/api/v1
```

There is no sandbox. Every request acts on your real computes, and a compute you create is billed.

## Authentication

Every endpoint except the health check needs an API key, sent as a bearer token:

```http
Authorization: Bearer YOUR_API_KEY
```

See [Create an API key](/api-reference/create-an-api-key).

A key belongs to one team and acts with the role of the member who created it. See [What each role can do](/services/teams/overview#what-each-role-can-do).

- If the member's role changes, the key follows the new role.
- If the member leaves the team or is removed, the key stops working.

<Warning>
  Anyone who has a key can act on your team with it. Do not put a key in a public repository, in code that runs in a browser, or in a forum post. If a key leaks, delete it in the dashboard at once.
</Warning>

## Requests

Send `POST` and `PATCH` bodies as JSON, with this header:

```http
Content-Type: application/json
```

## Responses

A successful answer:

```json
{
  "success": true,
  "message": "Operation successful",
  "data": { ... },
  "requestId": "59ea8f7e-...",
  "timestamp": "2024-01-15T10:00:00Z"
}
```

An error:

```json
{
  "success": false,
  "code": "RESOURCE_NOT_FOUND",
  "message": "The requested compute instance does not exist.",
  "requestId": "59ea8f7e-...",
  "timestamp": "2024-01-15T10:00:00Z"
}
```

| Field | Type | In | Meaning |
| :--- | :--- | :--- | :--- |
| `success` | boolean | both | `true` or `false`. |
| `message` | string | both | A sentence for people. It can change, so do not match on it. |
| `data` | object or array | success | The result. Left out when there is none. |
| `meta` | object | success, lists | See [Pagination](#pagination). |
| `code` | string | error | What went wrong. It does not change, so match on this. |
| `requestId` | string | both | Send it to support when you report a problem. |
| `timestamp` | string | both | When we answered. |

## Error codes

| Code | Status | Meaning |
| :--- | :---: | :--- |
| `BAD_REQUEST` | 400 | The request is malformed or a value is not valid. The `message` names the first problem. |
| `COMPUTE_RUNNING` | 400 | The compute must be stopped for this action. |
| `INSUFFICIENT_BALANCE` | 400 | The team's credits and funds do not cover one month of the price. |
| `UNAUTHORIZED` | 401 | The key is missing, wrong, expired or deleted, or its creator left the team. |
| `FORBIDDEN` | 403 | The role behind the key may not do this. |
| `TEAM_PAST_DUE` | 403 | The team owes money and cannot create computes until it is paid. |
| `TEAM_SUSPENDED` | 403 | The team is suspended for an unpaid amount. Only `GET` requests work. |
| `TEAM_TERMINATED` | 403 | The team is terminated for an unpaid amount. Only `GET` requests work. |
| `RESOURCE_NOT_FOUND` | 404 | There is no such compute, image, region or specification. |
| `CONFLICT` | 409 | The request conflicts with the current state of the compute. |
| `COMPUTE_DESTROYED` | 410 | The compute was destroyed. |
| `UNPROCESSABLE_ENTITY` | 422 | The request is well formed but cannot be carried out. |
| `TOO_MANY_REQUESTS` | 429 | You passed the [rate limit](#rate-limit). |
| `INTERNAL_SERVER_ERROR` | 500 | Something failed on our side. |
| `BAD_GATEWAY`, `SERVICE_UNAVAILABLE` | 502, 503 | A temporary problem on our side. Wait a few seconds and try again. |

## Pagination

[List computes](/api-reference/endpoint/list-computes) returns its result in pages.

| Parameter | Type | Default | Meaning |
| :--- | :--- | :--- | :--- |
| `page` | integer | `1` | The page to return. |
| `limit` | integer | `10` | How many computes a page holds. |

The answer has a `meta` object:

| Field | Type | Meaning |
| :--- | :--- | :--- |
| `total` | integer | How many computes there are over all pages. |
| `page` | integer | The page you got. |
| `limit` | integer | How many computes a page holds. |

```json
{
  "success": true,
  "data": [...],
  "meta": {
    "total": 42,
    "page": 1,
    "limit": 10
  }
}
```

## Idempotency

[Create a compute](/api-reference/endpoint/create-compute) needs an `Idempotency-Key` header, so that a request you send twice, for example after a timeout, creates one compute and not two.

```http
Idempotency-Key: YOUR_UNIQUE_KEY
```

- Use a new value for every compute you want to create. A UUID works well.
- If you send the same key again, you get the compute that the first request created. No second compute is created, and the answer is `202` both times.
- The body of the second request is not compared with the first. The same key with a different body still returns the first compute.
- A key is remembered for your team for as long as that compute exists.

## Rate limit

Each API key can send 2 requests a second. Past that, the API answers `429` with the code `TOO_MANY_REQUESTS`.

Every answer carries these headers:

| Header | Meaning |
| :--- | :--- |
| `X-RateLimit-Limit` | How many requests you can send in the current second. |
| `X-RateLimit-Remaining` | How many you have left in the current second. |
| `X-RateLimit-Reset` | When the count starts again, as a Unix timestamp in seconds. |
| `Retry-After` | On a `429` only: how many seconds to wait before you try again. |

If you need a higher limit, email [cloud@strettch.com](mailto:cloud@strettch.com).

## Versioning

The API version is `v1`, and it is part of every path.

We may add endpoints and fields to `v1` without notice, so your code should ignore fields it does not know. A change that could break your code comes in a new version, such as `/api/v2`. We announce it by email and in the [changelog](/changelog), and `v1` keeps working for a period that we state in the announcement.
