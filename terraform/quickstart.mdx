You create one compute with a public IP, log in to it over SSH, and destroy it. You pay for the compute and its public IP until you destroy them.

You need a Strettch Cloud team with enough credits or funds for the compute, and an SSH key pair on your computer. See [SSH Keys](/services/compute/ssh-keys) if you do not have one.

<Steps>
  <Step title="Install Terraform">
    Install Terraform from the [official downloads](https://developer.hashicorp.com/terraform/install), then check that it runs:

    ```bash
    terraform version
    ```
  </Step>

  <Step title="Create an API key">
    [Create an API key](/api-reference/create-an-api-key) in the dashboard, then give it to Terraform in an environment variable:

    ```bash
    export STRETTCH_CLOUD_API_KEY="YOUR_API_KEY"
    ```

    Treat the key like a password. Do not commit it to version control.
  </Step>

  <Step title="Configure the provider">
    Create a file named `main.tf` and declare the provider:

    ```hcl main.tf
    terraform {
      required_providers {
        strettchcloud = {
          source  = "strettch-cloud/strettchcloud"
          version = "~> 1.0"
        }
      }
    }

    provider "strettchcloud" {
      # api_key is read from STRETTCH_CLOUD_API_KEY
    }
    ```
  </Step>

  <Step title="Define a compute">
    Add a compute to `main.tf` and output its public IP. Replace the value of `public_keys` with your own SSH public key.

    ```hcl main.tf
    resource "strettchcloud_compute" "web" {
      host_name      = "web-01"
      image          = "UBUNTU-24.04"
      region         = "KGL-1"
      specification  = "S-1C-1G"
      public_keys    = ["ssh-ed25519 AAAA... you@example.com"]
      with_public_ip = true
      tags           = ["production", "web"]
    }

    output "public_ip" {
      value = strettchcloud_compute.web.ipv4
    }
    ```
  </Step>

  <Step title="Initialize and apply">
    Download the provider, look at the plan, then create the compute:

    ```bash
    terraform init
    terraform plan
    terraform apply
    ```

    When the apply finishes, Terraform prints the `public_ip` output.
  </Step>

  <Step title="Check that it works">
    Log in with the SSH key you provided. SSH to a compute uses [port 222](/services/compute/connect-to-a-compute#which-port-to-use).

    ```bash
    ssh root@$(terraform output -raw public_ip) -p 222
    ```
  </Step>

  <Step title="Destroy the compute">
    Destroy what you created so that billing stops:

    ```bash
    terraform destroy
    ```
  </Step>
</Steps>

## Look up images, regions and specifications

The slug of an image, a region or a specification can change. Look them up as data sources and use the result, so your files do not depend on a fixed slug:

<CodeGroup>
```hcl Images
data "strettchcloud_images" "all" {}

output "image_slugs" {
  value = data.strettchcloud_images.all.images[*].image
}
```

```hcl Regions
data "strettchcloud_regions" "all" {}

output "region_slugs" {
  value = data.strettchcloud_regions.all.regions[*].region
}
```

```hcl Specifications
data "strettchcloud_specifications" "all" {}

output "spec_slugs" {
  value = data.strettchcloud_specifications.all.specifications[*].specification
}
```
</CodeGroup>

You can also look up one entry. This example picks a specification by its CPU and RAM:

```hcl
data "strettchcloud_specification" "medium" {
  vcpus     = 2
  memory_mb = 4096
}

resource "strettchcloud_compute" "app" {
  host_name     = "app-01"
  image         = "UBUNTU-24.04"
  region        = "KGL-1"
  specification = data.strettchcloud_specification.medium.specification
  public_keys   = ["ssh-ed25519 AAAA... you@example.com"]
}
```
