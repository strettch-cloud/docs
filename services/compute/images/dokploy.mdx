Dokploy is a self-hosted platform for deploying applications and databases from a web dashboard. It builds with Docker, routes with Traefik and gets TLS certificates for you.

On this image Dokploy is installed but switched off. Its web port stays closed until you run setup, so nobody can claim the admin account before you do. Setup runs the first time you log in and takes about three minutes.

## What is on this image

Everything below is installed on Ubuntu 24.04.

| Software | What it does |
|---|---|
| Dokploy | The platform, with the Postgres and Traefik containers it runs on |
| Docker and Compose | Run Dokploy and whatever you deploy with it |
| `ufw` | Firewall, already configured. See [Security](#security) |
| `fail2ban` | Blocks IP addresses that keep failing SSH logins |
| `unattended-upgrades` | Installs Ubuntu security updates automatically |
| SC Agent (`sc-console-agent`) | Runs the [web console](/agents/sc-agent) |
| SC Metrics Agent (`sc-metrics-agent`) | Sends the values for the [compute graphs](/services/compute/compute-graphs) |

## 1. Connect

When the compute is running, connect over SSH as `root`, with the root password or the SSH key you chose when you created it:

```bash
ssh root@YOUR_COMPUTE_IP -p 222
```

Setup starts when you log in. If you use the [web console](/services/compute/connect-to-a-compute#open-the-web-console) instead, start setup yourself:

```bash
/opt/sc/dokploy/setup.sh
```

## 2. Answer three questions

Setup asks for:

- **Admin email**: the email you will log in to Dokploy with.
- **Your name**: shown as your display name. Press Enter to accept `Admin`.
- **Admin password**: at least twelve characters. You type it twice.

<Warning>
  Choose a strong password and store it. Whoever has the Dokploy admin login controls the whole compute. The password is not saved on the compute, so only you have it.
</Warning>

## 3. Log in

When setup finishes, it prints your URL. Open it:

```
http://YOUR_COMPUTE_IP:3000
```

Use the public IP of the compute, which is on its page in the dashboard. Log in with the email and the password you gave to setup.

## 4. Add a domain and HTTPS

This step is optional. Point an A record at the public IP of the compute, then set the domain in the Dokploy dashboard. Dokploy requests a certificate for it. Ports 80 and 443 are already open. The Dokploy documentation is at [docs.dokploy.com](https://docs.dokploy.com).

## Managing it

| Command | What it does |
|---|---|
| `/opt/sc/dokploy/info.sh` | Prints your URL and admin email again |
| `/opt/sc/dokploy/status.sh` | Shows whether Dokploy is running, which ports are open, and disk usage |
| `/opt/sc/dokploy/debug.sh` | Collects logs for support, with secrets removed |

## Security

The firewall allows SSH, HTTP, HTTPS, the Dokploy dashboard and the SC Agent. It blocks every other incoming connection.

`fail2ban` watches SSH. Ten failed logins block an IP address for six hours. An address that keeps failing is blocked for longer, up to a week.

To see both:

```bash
fail2ban-client status sshd
ufw status
```

If you cancel setup or mistype an answer, nothing is exposed. Log in again and setup starts over.
