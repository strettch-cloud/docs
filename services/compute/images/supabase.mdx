Supabase gives you a Postgres database with authentication, file storage, realtime subscriptions and generated APIs, managed from its Studio dashboard.

On this image all of Supabase is installed but switched off, and its gateway is closed, so nobody can reach your database before you do. Setup asks no questions. It runs the first time you log in and takes about five minutes, because it starts eleven services.

## What is on this image

Everything below is installed on Ubuntu 24.04.

| Software | What it does |
|---|---|
| Supabase | All eleven services: Postgres, Auth, Storage, Realtime, Studio, the Kong gateway and the rest |
| Docker and Compose | Run Supabase |
| `git`, `jq`, `openssl` | Used by the setup and management scripts |
| `ufw` | Firewall, already configured. See [Security](#security) |
| `fail2ban` | Blocks IP addresses that keep failing SSH logins |
| `unattended-upgrades` | Installs Ubuntu security updates automatically |
| SC Agent (`sc-console-agent`) | Runs the [web console](/agents/sc-agent) |
| SC Metrics Agent (`sc-metrics-agent`) | Sends the values for the [compute graphs](/services/compute/compute-graphs) |

## 1. Connect

When the compute is running, connect over SSH as `root`, with the root password or the SSH key you chose when you created it:

```bash
ssh root@YOUR_COMPUTE_IP -p 222
```

Setup starts when you log in. If you use the [web console](/services/compute/connect-to-a-compute#open-the-web-console) instead, start setup yourself:

```bash
/opt/sc/supabase/setup.sh
```

Setup creates the secrets and API keys for this compute, starts Supabase, and waits until the database, Auth and Studio answer.

## 2. Open Studio

When setup finishes, it prints your URL, username and password. Open the URL:

```
http://YOUR_COMPUTE_IP:8000
```

Use the public IP of the compute, which is on its page in the dashboard. Copy the password into your password manager now. Anyone who has this login can open your database dashboard from the internet.

## 3. Get your API keys

One command prints your `anon` and `service_role` keys, the database password and the connection strings:

```bash
cd /root/supabase-project && sh run.sh secrets
```

Point your application at `http://YOUR_COMPUTE_IP:8000` with the `anon` key.

<Warning>
  Keep the `service_role` key on your server. Never put it in code that runs in a browser or an app. It skips row-level security, so anyone who has it can read and change all your data.
</Warning>

## 4. Add a domain and HTTPS

Do this early. Until you do, traffic to Studio and to your APIs is not encrypted. Point an A record at the public IP of the compute, then run:

```bash
cd /root/supabase-project && sh run.sh config add caddy
```

You can use nginx instead of Caddy. Supabase documents both at [supabase.com/docs/guides/self-hosting](https://supabase.com/docs/guides/self-hosting).

## Managing it

| Command | What it does |
|---|---|
| `/opt/sc/supabase/info.sh` | Prints your Studio URL and login again |
| `/opt/sc/supabase/status.sh` | Shows whether Supabase is running, which ports are open, and disk usage |
| `/opt/sc/supabase/debug.sh` | Collects logs for support, with secrets removed |
| `cd /root/supabase-project && sh run.sh {status,logs,restart}` | Shows the status or logs of the services, or restarts them |

## Security

The firewall allows SSH, the Supabase gateway and the SC Agent. It blocks every other incoming connection.

`fail2ban` watches SSH. Ten failed logins block an IP address for six hours. An address that keeps failing is blocked for longer, up to a week.

To see both:

```bash
fail2ban-client status sshd
ufw status
```

<Warning>
  Docker can publish a port past `ufw`, even when `ufw status` shows the port as blocked. Whether Postgres can be reached from the internet depends on the ports that Supabase's Docker setup publishes. Check from another machine:

  ```bash
  nc -zv YOUR_COMPUTE_IP 5432
  ```
</Warning>

If setup is interrupted, nothing is exposed. Log in again and setup starts over.
