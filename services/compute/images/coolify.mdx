Coolify is a self-hosted platform for deploying applications, databases and services from a web dashboard.

On this image Coolify is installed but switched off. Its web port stays closed until you run setup, so nobody can claim the admin account before you do. Setup runs the first time you log in and takes about three minutes.

## What is on this image

Everything below is installed on Ubuntu 24.04.

| Software | What it does |
|---|---|
| Coolify | The platform, with the Postgres and Redis containers it runs on |
| Docker and Compose | Run Coolify and whatever you deploy with it |
| `ufw` | Firewall, already configured. See [Security](#security) |
| `fail2ban` | Blocks IP addresses that keep failing SSH logins |
| `unattended-upgrades` | Installs Ubuntu security updates automatically |
| SC Agent (`sc-console-agent`) | Runs the [web console](/agents/sc-agent) |
| SC Metrics Agent (`sc-metrics-agent`) | Sends the values for the [compute graphs](/services/compute/compute-graphs) |

## 1. Connect

When the compute is running, connect over SSH as `root`, with the root password or the SSH key you chose when you created it:

```bash
ssh root@YOUR_COMPUTE_IP -p 222
```

Setup starts when you log in. If you use the [web console](/services/compute/connect-to-a-compute#open-the-web-console) instead, start setup yourself:

```bash
/opt/sc/coolify/setup.sh
```

## 2. Answer three questions

Setup asks for:

- **Admin email**: the email you will log in to Coolify with.
- **Domain name**: optional. Leave it empty and Coolify uses the IP address of the compute.
- **SMTP**: optional. Answer `n`. You can add it later in Coolify.

Coolify creates the admin password and prints it at the end.

## 3. Log in

When setup finishes, it prints your URL, email and password. Open the URL:

```
http://YOUR_COMPUTE_IP:8000
```

Use the public IP of the compute, which is on its page in the dashboard. Log in with the email and the password that setup printed.

<Warning>
  Setup also saves the password in a file on the compute. Copy the password into your password manager, then delete the file:

  ```bash
  rm /root/.sc-credentials
  ```
</Warning>

Coolify then takes you through its own first steps. They change between releases, so follow what Coolify shows. Its documentation is at [coolify.io/docs](https://coolify.io/docs).

## 4. Add a domain and HTTPS

This step is optional. Point an A record at the public IP of the compute, then set the domain in Coolify. Coolify requests a certificate for it. Ports 80 and 443 are already open.

## Managing it

| Command | What it does |
|---|---|
| `/opt/sc/coolify/info.sh` | Prints your URL and admin email again |
| `/opt/sc/coolify/status.sh` | Shows whether Coolify is running, which ports are open, and disk usage |
| `/opt/sc/coolify/debug.sh` | Collects logs for support, with secrets removed |

## Security

The firewall allows SSH, HTTP, HTTPS, the Coolify dashboard and the SC Agent. It blocks every other incoming connection.

`fail2ban` watches SSH. Ten failed logins block an IP address for six hours. An address that keeps failing is blocked for longer, up to a week.

To see both:

```bash
fail2ban-client status sshd
ufw status
```

If you cancel setup or mistype an answer, nothing is exposed. Log in again and setup starts over.
